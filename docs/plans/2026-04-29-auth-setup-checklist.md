# Auth Setup Checklist

External configuration only Ethan can do. Required before Google / Apple sign-in code paths will actually authenticate users. Code-side wiring is tracked separately in tasks.

**Project identifiers** (reference these as you go):

| Field                   | Value                                               |
| ----------------------- | --------------------------------------------------- |
| iOS bundle ID           | `com.ghanbak.ossusarchives`                         |
| Android package         | `com.ghanbak.ossusarchives` _(set during prebuild)_ |
| URL scheme              | `ossusarchives`                                     |
| Local Supabase URL      | `http://192.168.1.9:54321`                          |
| Production Supabase URL | _(not yet provisioned)_                             |

---

## 1. Supabase Project (cloud)

The local Supabase works for dev, but Google/Apple OAuth needs a public callback URL. Create a hosted project for testing real sign-in.

- [x] Sign in to https://supabase.com/dashboard
- [x] **New project** → name `ossus-archives`, region close to you, generate strong DB password (save it)
- [x] Wait for provisioning (~2 min)
- [x] Copy **Project URL** (`https://<ref>.supabase.co`) and **anon key** from Settings → API
- [x] Note the **Auth callback URL**: `https://<ref>.supabase.co/auth/v1/callback`
- [x] Run migrations against the new project: `supabase link --project-ref <ref>` then `supabase db push`
- [x] Run seed: `supabase db seed` (or re-run `npm run db:seed` against the cloud URL)
- [x] Add a `.env.production` (or swap `.env`) with the cloud URL + anon key when testing real auth

## 2. Google Cloud Console

Goal: produce three OAuth Client IDs (Web, iOS, Android) and wire the Web client into Supabase.

### 2a. Project + OAuth consent screen

- [x] Go to https://console.cloud.google.com
- [x] Create new project: `ossus-archives`
- [x] **APIs & Services → OAuth consent screen**
  - [x] User type: **External**
  - [x] App name: `OssusArchives`
  - [x] User support email: your email
  - [x] Developer contact: your email
  - [x] Scopes: leave defaults (email, profile, openid)
  - [x] Test users: add your Google account (until you publish)
  - [x] Save

### 2b. Web Client ID (used by Supabase to verify ID tokens)

- [x] **APIs & Services → Credentials → + Create Credentials → OAuth client ID**
- [x] Application type: **Web application**
- [x] Name: `OssusArchives — Web (Supabase)`
- [x] **Authorized redirect URIs:** add `https://<your-ref>.supabase.co/auth/v1/callback`
- [x] Create → copy **Client ID** and **Client secret**

### 2c. iOS Client ID

- [x] **+ Create Credentials → OAuth client ID**
- [x] Application type: **iOS**
- [x] Name: `OssusArchives — iOS`
- [x] Bundle ID: `com.ghanbak.ossusarchives`
- [x] Create → copy **Client ID**
- [x] Note the **iOS URL scheme** (reverse of client ID, like `com.googleusercontent.apps.123-abc`) — replace the `PLACEHOLDER-REPLACE-WITH-IOS-CLIENT-ID` value in `app.json` (`@react-native-google-signin/google-signin` plugin → `iosUrlScheme`), then re-run `npx expo prebuild --clean` and `npx expo run:ios`

### 2d. Android Client ID

> **Deferred until Android release.** iOS-first launch — Android Client ID, package signing, and Play Store work all happen together in a later phase. The `android/` directory is regenerated by `expo prebuild` and the package name is already correct (`com.ghanbak.ossusarchives`); no action needed until ready to ship Android.

You need the SHA-1 of your debug keystore.

- [ ] After running `expo prebuild` once, get debug SHA-1:
      `keytool -keystore ~/.android/debug.keystore -list -v` (password: `android`)
- [ ] **+ Create Credentials → OAuth client ID**
- [ ] Application type: **Android**
- [ ] Name: `OssusArchives — Android (debug)`
- [ ] Package name: `com.ghanbak.ossusarchives`
- [ ] SHA-1: paste from above
- [ ] Create → copy **Client ID**
- [ ] Repeat later for the EAS production keystore SHA-1 when you build for Play Store

### 2e. Hand the Web client to Supabase

- [x] Supabase Dashboard → **Authentication → Providers → Google**
- [x] Enable
- [x] Paste **Client ID** (Web) and **Client Secret** (Web)
- [x] **Skip nonce check:** off (default)
- [x] Save

The Web Client ID is also passed to `GoogleSignin.configure({ webClientId })` in the app.

## 3. Apple Developer

Goal: enable Sign in with Apple on the App ID and configure Supabase.

- [x] Sign in to https://developer.apple.com/account
- [x] **Identifiers → App IDs**
  - [x] Find or create `com.ghanbak.ossusarchives`
  - [x] Edit → check **Sign In with Apple** capability
  - [x] Save
- [x] **Identifiers → Services IDs** _(only needed for the Supabase web callback flow — not for native iOS sign-in, but Supabase requires it to verify tokens)_
  - [x] - → **Services IDs**
  - [x] Description: `OssusArchives`
  - [x] Identifier: `com.ghanbak.ossusarchives.signin` (must differ from app bundle ID)
  - [x] Configure → enable **Sign In with Apple**
    - [x] Primary App ID: `com.ghanbak.ossusarchives`
    - [x] Domains: `<your-ref>.supabase.co`
    - [x] Return URLs: `https://<your-ref>.supabase.co/auth/v1/callback`
  - [x] Save → Continue → Register
- [x] **Keys → +**
  - [x] Name: `OssusArchives — Sign in with Apple`
  - [x] Enable **Sign In with Apple** → Configure → Primary App ID `com.ghanbak.ossusarchives` → Save
  - [x] Continue → Register → **Download** the `.p8` key file (one-time download, save it)
  - [x] Note the **Key ID** (10 chars)
  - [x] Note your **Team ID** (top-right of Apple Developer site)

### Hand it to Supabase

- [x] Supabase Dashboard → **Authentication → Providers → Apple**
- [x] Enable
- [x] **Client IDs:** `com.ghanbak.ossusarchives,com.ghanbak.ossusarchives.signin` _(comma-separated: native bundle ID first, then Service ID)_
- [x] **Secret Key (for OAuth):** generate via:
      `sh
  # Use a one-shot script or jwt.io. Supabase has a generator at:
  # https://supabase.com/docs/guides/auth/social-login/auth-apple#generate-a-client-secret
  `    Inputs needed: Team ID, Key ID, Service ID, contents of`.p8`. Output is a JWT valid 6 months — note an expiry reminder.
- [x] Save
