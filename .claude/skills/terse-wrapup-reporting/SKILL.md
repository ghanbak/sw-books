# Terse wrap-up reports

End with the result, one line per change, then only the decisions the user must make.

- No verification recap and no replay of the steps taken.
- No headers or tables unless the user asked for a comparison; a short list of changes is enough.
- Name anything not done yet (commit, push, auth step) as a single action line.
- Brevity beats narration detail when the two conflict.
